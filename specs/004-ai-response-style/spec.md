## User Scenarios & Testing *(mandatory)*

### User Story 1 - 자연스러운 대화형 응답 (Priority: P1)

사용자가 "김철수가 뭘 했어?"라고 질문하면, 단순히 "5건의 결과를 찾았습니다" 대신 "김철수님은 다음과 같은 작업을 수행했습니다"처럼 질문의 맥락을 이해하고 자연스러운 문장으로 답변한다.

**Why this priority**: 사용자 경험의 핵심 요소로, AI 서비스의 가치를 결정짓는 가장 중요한 기능

**Independent Test**: 자연어 질문 후 응답이 대화형 문장인지 확인하여 테스트 가능

**Acceptance Scenarios**:

1. **Given** Excel 파일이 로드된 상태, **When** 사용자가 "김철수가 뭘 했어?"라고 질문, **Then** "김철수님은 [날짜]에 [작업내용]을 수행했습니다" 형태의 자연스러운 문장으로 응답
2. **Given** Excel 파일이 로드된 상태, **When** 사용자가 "오늘 누가 일했어?"라고 질문, **Then** "오늘 작업한 인원은 [이름1], [이름2] 등 총 N명입니다" 형태로 응답
3. **Given** 검색 결과가 없는 상태, **When** 사용자가 존재하지 않는 데이터를 질문, **Then** "해당 조건에 맞는 데이터를 찾을 수 없습니다. 다른 조건으로 검색해보시겠어요?" 형태로 안내

---

### User Story 2 - 데이터 요약 및 인사이트 제공 (Priority: P2)

조회된 데이터가 여러 건일 때, 단순 나열이 아닌 요약 정보와 함께 주요 패턴이나 특이사항을 함께 안내한다.

**Why this priority**: 사용자가 대량의 데이터를 빠르게 파악할 수 있게 도와주는 부가 가치 기능

**Independent Test**: 다건 조회 후 요약 문구가 포함되는지 확인하여 테스트 가능

**Acceptance Scenarios**:

1. **Given** 10건 이상의 결과가 있는 상태, **When** 결과 표시, **Then** "총 N건의 결과가 있으며, 가장 많은 작업은 [작업유형]입니다" 형태의 요약 포함
2. **Given** 날짜 범위 질문, **When** 기간별 데이터 조회, **Then** "해당 기간 동안 총 N건의 작업이 있었으며, [날짜]에 가장 많은 활동이 있었습니다" 형태로 응답

---

### User Story 3 - 후속 질문 안내 (Priority: P3)

응답 후 관련된 추가 질문을 제안하여 사용자가 더 깊이 탐색할 수 있도록 안내한다.

**Why this priority**: 사용자 편의성 향상 기능으로, 핵심 기능 이후 추가 개선 사항

**Independent Test**: 응답 하단에 추천 질문이 표시되는지 확인하여 테스트 가능

**Acceptance Scenarios**:

1. **Given** 특정 직원 조회 완료, **When** 결과 표시 후, **Then** "더 알고 싶으시면: '[직원명]의 이번 달 실적은?', '[직원명]이 담당한 설비는?'" 형태의 후속 질문 제안

---

### Edge Cases

- 결과가 0건일 때 친절한 안내 메시지 제공
- 결과가 100건 이상일 때 요약 중심으로 응답
- 질문이 불명확할 때 명확화 요청
- 데이터 타입별(숫자, 날짜, 텍스트) 적절한 표현 방식 적용

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 LLM을 활용하여 SQL 조회 결과를 질문의 맥락에 맞는 자연어 문장으로 변환하여 응답해야 한다
- **FR-002**: 시스템은 조회 결과 건수에 따라 다른 형식의 응답을 생성해야 한다 (1건/소수건/다건/0건)
- **FR-003**: 시스템은 조회된 데이터의 핵심 내용을 응답 문장에 포함해야 한다
- **FR-004**: 시스템은 결과가 없을 때 대안을 제시하는 친절한 메시지를 표시해야 한다
- **FR-005**: 시스템은 다건 조회 시 요약 정보를 함께 제공해야 한다
- **FR-006**: 시스템은 응답에 적절한 존칭과 자연스러운 어미를 사용해야 한다

### Key Entities

- **QueryContext**: 사용자 질문, 의도 분류, 관련 시트 정보
- **ResponseTemplate**: 응답 유형별 템플릿 (단건/다건/빈결과/오류)
- **AnswerSummary**: 결과 요약 정보 (총건수, 주요 패턴, 특이사항)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 응답이 완전한 자연어 문장 형태로 제공된다 (단순 건수 표시가 아닌 맥락 있는 문장)
- **SC-002**: 사용자가 응답을 읽고 추가 질문 없이 결과를 이해할 수 있다
- **SC-003**: 0건 결과 시 100%의 경우 대안 제시 문구가 포함된다
- **SC-004**: 10건 이상 결과 시 요약 정보가 응답에 포함된다
- **SC-005**: 응답 생성 시간이 기존 대비 2초 이내 추가 소요
