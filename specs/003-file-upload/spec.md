# Feature Specification: UI 파일 업로드 기능 개선

**Feature Branch**: `003-file-upload`
**Created**: 2025-12-23
**Status**: Draft
**Input**: User description: "UI에서 파일 업로드 해서 테스트하려고 하는데 잘 안돼"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Excel 파일 업로드 (Priority: P1)

사용자가 Chainlit UI에서 Excel 파일(.xlsx, .xls)을 업로드하면 시스템이 파일을 수신하고 로드하여 자연어 질의가 가능한 상태가 된다.

**Why this priority**: 파일 업로드가 전체 시스템의 진입점이므로, 이 기능이 작동하지 않으면 어떤 질의도 불가능하다.

**Independent Test**: Excel 파일을 업로드하면 시트 목록과 파일 정보가 표시되어야 한다.

**Acceptance Scenarios**:

1. **Given** UI가 열린 상태, **When** 사용자가 클립 아이콘을 클릭하고 .xlsx 파일을 선택, **Then** 파일이 업로드되고 "파일 로드 완료" 메시지와 시트 정보가 표시됨
2. **Given** UI가 열린 상태, **When** 사용자가 .xls 파일을 드래그앤드롭, **Then** 파일이 업로드되고 정상적으로 처리됨
3. **Given** 파일 업로드 중, **When** 로딩이 진행되는 동안, **Then** "파일을 로딩 중..." 메시지가 표시됨

---

### User Story 2 - 업로드 오류 피드백 (Priority: P1)

사용자가 지원되지 않는 파일을 업로드하거나 오류가 발생했을 때 명확한 오류 메시지를 받는다.

**Why this priority**: 사용자가 왜 업로드가 안 되는지 이해해야 문제를 해결할 수 있다.

**Independent Test**: 잘못된 파일 형식을 업로드하면 명확한 오류 메시지가 표시되어야 한다.

**Acceptance Scenarios**:

1. **Given** UI가 열린 상태, **When** 사용자가 .pdf 파일을 업로드, **Then** "Excel 파일(.xlsx, .xls)만 지원됩니다" 오류 메시지 표시
2. **Given** UI가 열린 상태, **When** 손상된 Excel 파일을 업로드, **Then** 적절한 오류 메시지와 함께 재시도 안내 표시
3. **Given** 파일 업로드 시도, **When** 네트워크 오류 발생, **Then** "파일 업로드 실패. 다시 시도해주세요" 메시지 표시

---

### User Story 3 - 업로드 후 질의 가능 상태 확인 (Priority: P2)

파일 업로드 완료 후 시스템이 질의 가능한 상태임을 사용자에게 명확히 알린다.

**Why this priority**: 사용자가 언제 질문을 시작해도 되는지 알아야 한다.

**Independent Test**: 파일 로드 완료 후 질문 예시와 함께 사용 가능 상태가 표시되어야 한다.

**Acceptance Scenarios**:

1. **Given** 파일 업로드 완료, **When** 로드 성공, **Then** "이제 자연어로 질문해보세요!" 메시지와 예시 질문 표시
2. **Given** 파일 업로드 완료, **When** 사용자가 질문 입력, **Then** 정상적으로 SQL 생성 및 응답 반환

---

### Edge Cases

- 파일 크기가 10MB 이상일 때 타임아웃 처리
- 시트 수가 50개 이상인 대용량 파일 처리
- 한글이 포함된 파일명/시트명 처리
- 빈 시트만 있는 파일 처리
- 사용자가 파일 업로드 중 취소할 때

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 Chainlit UI에서 파일 첨부 기능을 활성화해야 한다 (config.toml 설정)
- **FR-002**: 시스템은 .xlsx 및 .xls 확장자의 Excel 파일을 수락해야 한다
- **FR-003**: 시스템은 클릭 및 드래그앤드롭 방식의 파일 업로드를 지원해야 한다
- **FR-004**: 시스템은 파일 업로드 진행 상태를 사용자에게 표시해야 한다
- **FR-005**: 시스템은 지원하지 않는 파일 형식에 대해 명확한 오류 메시지를 표시해야 한다
- **FR-006**: 시스템은 파일 로드 완료 후 파일 정보(크기, 시트 수, 행 수)를 표시해야 한다
- **FR-007**: 시스템은 업로드된 파일의 시트 목록과 컬럼 정보를 요약하여 표시해야 한다
- **FR-008**: 시스템은 한 세션에서 하나의 파일만 활성화하되, 새 파일 업로드 시 기존 파일을 대체해야 한다
- **FR-009**: 시스템은 파일 처리 오류 시 사용자가 이해할 수 있는 오류 메시지를 제공해야 한다

### Key Entities

- **업로드 파일**: Excel 파일, 파일명, 확장자, 크기, 업로드 시간
- **세션 컨텍스트**: 현재 로드된 파일 정보, 스키마, 질의 가능 상태

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 Excel 파일을 업로드하면 10초 이내에 로드 완료 메시지가 표시된다 (3MB 기준)
- **SC-002**: 파일 업로드 버튼(클립 아이콘)이 UI에서 명확히 보이고 클릭 가능하다
- **SC-003**: 지원하지 않는 파일 형식 업로드 시 2초 이내에 오류 메시지가 표시된다
- **SC-004**: 파일 로드 완료 후 100%의 확률로 자연어 질의가 가능한 상태가 된다
- **SC-005**: 한글 파일명/시트명이 포함된 파일도 정상적으로 처리된다

## Assumptions

- Chainlit config.toml 파일이 필요하며, multi_modal 설정을 통해 파일 업로드 활성화 필요
- Docker 컨테이너 환경에서 파일 업로드 시 임시 파일 경로 접근 가능해야 함
- LLM 서버(Ollama)가 정상 작동 중이어야 질의 기능이 동작함
